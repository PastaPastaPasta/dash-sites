Name, record, files

A .dash site is three kinds of document on Dash Platform. Opening one means following them in order and checking each step.

  1. You ask for built4.dash

    Open it on dash.site as built4.dash.site, or type the name itself with the extension pointed at dash.site and set to mainnet.

  2. Name document …
    owned by …

    Names live in Dash Platform's name service, DPNS. The reader asks for the name's document and gets it with a proof signed by the network's validators. The document's owner is the only identity whose site will be shown.

  3. Site document …
    revision …, content …

    The owner keeps one site document per name. It holds a single line: the hash of the site's manifest. Publishing a new version replaces that line, and the revision goes up by one.

  4. Manifest: … files in … chunk documents

    The manifest lists every file with its type, size and SHA-256 hash, and says which chunks hold its bytes. Chunks are documents too, named by their own hash, so identical content is stored once.

  5. Files, checked against their hashes

    The reader fetches the chunks a page needs, joins them, and compares the result with the hash in the manifest. Anything that does not match is refused rather than shown.

Who does the checking

Your browser, in any browser

Open https://built4.dash.site/. dash.site is a static site: it sends one small page, the same for every name, a service worker and a verifier pinned by its hash. From then on your browser talks to Dash Platform nodes itself: it proves the name and the site record, fetches the files, checks each hash, and shows the site.

That is how you are reading this page. The host that sent the verifier has not seen or sent a byte of it.

You are reading a copy the server rendered instead, as it does for crawlers, link previews and command-line tools.

After the first visit the installed worker keeps the site working even if dash.site disappears.

The extension, by its real name

With the extension pointed at dash.site and set to mainnet, you type built4.dash and land on the same verifier. Its button asks Dash Platform a second time, with its own copy of the SDK, and compares the answer with the page in front of you.

What you still have to trust

The network's validators

A proof shows that a quorum of Dash masternodes signed the state a record belongs to. That is the same guarantee Dash Platform gives every application built on it.

The list of validator keys

To check a signature the verifier needs the quorums' public keys. Today the Dash SDK downloads them from a service run by Dash Core Group. Whoever controls that service is trusted not to lie about the keys.

The verifier you were sent

The checking code comes from dash.site. It is open source and the same for every name, and the service worker refuses a verifier whose SHA-256 does not match the one it carries. A dishonest host could still send a different service worker. Serving the static page from your own machine removes that.

The owner of the name

Proofs show a site is what the owner published. They say nothing about whether the owner is honest. Treat a .dash site like any other site you have not visited before.
