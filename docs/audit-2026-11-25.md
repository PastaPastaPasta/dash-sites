## Product questions

1. **Size of the Forge copy.** The SDK wasm (about 26.5 MB) counts toward the reader's 50 MB site
   limit even though it is not stored (row 21). Before the 0.82 DASH mainnet publish of
   forg3.dash.site, confirm the whole export fits (`dash-sites publish … --dry-run`), or decide
   whether external files should count.
2. **Network of `build:dash-site`.** It inherits the default testnet build (rows 46-47). Should
   `dash-site-postbuild.mjs --check` require `NEXT_PUBLIC_NETWORK=mainnet` when the site URL is
   under dash.site? That is a behavior change, so it is not made here.
3. **Testnet host and extension are behind.** `id.dashhq.org` runs a shell from before the brotli
   wasm split and before manifest version 2; extension 0.1.0 also predates version 2. Redeploy
   `id.dashhq.org` and cut an extension release so testnet copies of version 2 sites open there.
4. **IPv6 for the DNS-01 responder.** `deploy/provision.sh` takes only an IPv4 address and agnos
   listens only on it. The host itself is dual-stack. Should the responder also listen on IPv6?
5. **Shared denied-page copy.** `DENIED_TITLE` ("Unavailable on this gateway") is right for
   `id.dashhq.org`, but the planned dash.site blocking Worker should not reuse it, since dash.site is
   a static site.
6. **DESIGN.md status line** (row 30) should say mainnet is live when PR #14 lands.
